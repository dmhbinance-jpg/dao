### 关键约定（沿用 V0）
- 不用 ES modules；新文件同时加到 `index.html`（和 `v0.html`，如果它也要用）与 `src/node.js`。
- 逻辑层不碰 DOM：`src/core`、`src/config`、`src/battle`、`src/game` 里没有浏览器 API。
- 所有数值进 `DAO.CONFIG`：阶段 0 的数值都在 `CONFIG.stage0`，播放节奏在 `CONFIG.playback`。
- 随机只走 `battle.rng`。存档里的 `seedCounter` 决定下一场的种子，每结算一场 +1。

### 阶段 0 的规则怎么落地
- **开局角色没有特例**：`Stage0.heroChar()` 把存档里的角色转成和其他角色同样字段的定义（role / base / growth / innate / talents），交给同一个 `buildUnit`。
- **只有普攻 + 固有主动**：`activeCard` / `passiveCard` 为空；固有主动固定用 A 分支（剑修「剑气斩·单」，法修「连珠火·散」）。2选1 没有界面。
- **一场战斗两步走**：`runBattle`（只算，不改存档）→ `applyOutcome`（经验、升级、通关、种子）。手动战斗播完 / 跳过 / 离开时结算；挂机等计时结束再结算，中途停止就作废这一场。
- **经验**：击杀经验 = 敌人模板 `exp` × 敌人等级 × `killMul`(2)；战败时已击杀的照样给（`lossKeepsKills`）。升级所需 = round(10 × 等级^1.6)。每场开打都是满血。
- **挂机**：只能挂已通关的关卡；刷新页面会继续挂机，但不补离线收益。开始手动挑战会停掉挂机。
- **存档**：`localStorage['dao.s0.save']`，`v: 1`，和 V0 的 `dao.v0.*` 分开。版本号对不上就当没有存档（回到选角）。

### 配置改动对 V0 的影响
- 气血公式改成 `(200 + 60 × 等级) × 定位倍率`（原来 1000 + 40×等级），低等级才有意义。V0 的 30 级角色气血从 2200 降到 2000，加上奶妈没了，V0 默认对局从约 26 回合变成约 6 回合。V0 报告已重跑。
- 定位表只剩 `sword` / `mage`，另加敌人用的 `beast`（妖兽，近战）/ `demon`（妖修，远程）。
- 名将霍骁改为剑修；「破军之威」的专属判断从定位改为角色 id。

## 阶段 0 观察到的设计问题（带回设计对话）
1. **胜率随等级跳变很陡**：多数关卡从 0% 到 90%+ 只差 1–2 级（见报告胜率表）。原因是没有伤害浮动，唯一随机是暴击。手感是「差一级打不过，升一级碾压」，挂机目标清楚，但战斗本身悬念少。
2. **用时大部分在挂机**：约 13 分钟里，手动 17–18 场，挂机 50–66 场。引导阶段是否希望挂机占这么大比例？
3. **法修稳定落后约 1 级**：气血薄，首领单挑时弹射全落在首领身上也追不回来。在要求范围内（≤2 级），但如果希望两者完全对等，需要调法修气血倍率或首领。
4. **战败也给击杀经验**：任务说明写「击杀得经验」，所以输了也给。如果希望战败没有收益，把 `lossKeepsKills` 设为 false 即可。
5. **首领没有机制**：山魈只是血厚、有一个前排形状技能。阶段 0 没要求机制；后续首领要不要有阶段转换等，需要设计。
6. **固有主动的 2选1 先固定了 A 分支**：剑修拿单体（打首领强、打群怪弱），法修拿弹射（群怪和单体都不差）。阶段 1 之后开放 2选1 时，开局角色默认哪个分支要定。
