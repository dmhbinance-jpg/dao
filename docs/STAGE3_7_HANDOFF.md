# 交接说明（阶段 3.7 → 下一个对话）

## 一句话状态
阶段 3.7 完成，做了三件事：
- **存档保护**：读不出来的存档不再被当成「没有存档」，也不会被覆盖。迁移前先备份原始存档，保存时自动轮换备份。从本地服务打开时，存档同时写到仓库 `saves/`。
- **标题页与存档位**：打开先进标题页，有 3 个存档位。老存档自动进第 1 位。顶栏的「重新开始」换成了「存档」。

存档升到 v7。本阶段只走流程，没做数值验证。

## 之前存档丢失的原因（查代码得出）
用户的浏览器数据看不到，下面这几条是从 3.6 及以前的代码里查出来的、确实会丢档或「看起来丢档」的路径。按可能性排序：

1. **旧版本页面收到新版本存档时把存档删了（最主要）**
   - 3.6 及以前的 `game-app.js` 监听 `storage` 事件：别的页面一改 `dao.save`，它就重新读档。
   - 读不出来（`Game.migrate` 返回 null）时，它直接调 `resetGame()`，而 `resetGame()` 会执行 `store.del('save')`。
   - 每次升存档版本（v3 → v4 → v5 → v6）都会触发：
     - 一个标签页还开着旧代码，另一个标签页（或刷新后的新代码）把存档写成了新版本。
     - 旧代码不认识新版本号，`migrate` 返回 null，于是把存档删掉。
     - 存档工具页写存档时也会触发同一个事件。
2. **读不出来 = 没有存档**
   - `load()` 把 `migrate` 返回 null（版本号比代码新、`isValidV2` 校验没过、迁移代码出错）一律当成「没有存档」，直接进选角页。
   - 这时一开新游戏，原来的存档就被覆盖了。
3. **网址不同，存档是分开的**
   - 浏览器存档按网址隔离。下面每种打开方式都各有一份、互相看不见：
     - 双击 `index.html`（file://）
     - `http://localhost:8765`
     - 换了端口的 localhost
     - claude.ai 上发布的试玩页
   - 换一种方式打开，就像「存档没了」。阶段 3.5 起开始用本地服务，所以这条很可能也出现过。
4. **「重新开始」直接删档**：两次点击就删，没有备份。

本阶段的对应改法：
- **第 1、2 条**：存档位里读不出来的数据永远不删、不自动覆盖。别的页面写进来读不出来的数据时，本页停下回标题页。所有覆盖和删除之前都先备份。
- **第 3 条**：从本地服务打开时，存档同时写硬盘 `saves/`，换端口、清浏览器数据都能读回。
- **第 4 条**：去掉「重新开始」按钮；删除改到标题页，要二次确认，删前留备份。

还要注意一点：**升级前还开着的旧版本标签页仍然是旧代码**。它用的是老键 `dao.save`，新代码只在第一次打开时把它复制进第 1 个存档位，之后不再读写这个键，所以旧标签页删不到新存档。但更新代码后最好把旧标签页都关掉，或者刷新一下。

## 规则怎么落地

### 配置 `CONFIG.saves`（`src/config/game.js`）
`{ slots: 3, backups: 5, backupEveryMs: 300000, originals: 3, diskThrottleMs: 3000 }`。配置网站里在「其他」分类，`tools/validate.js` 加了范围检查。

### 存档位 `src/game/save-slots.js`（`DAO.SaveSlots`）
- 不碰 DOM，只管「键 → 字符串」。浏览器里传 `browserStorage(localStorage)`，命令行检查传 `memoryStorage()`。
- 用到的键：

  | 键 | 内容 |
  |---|---|
  | `dao.slot.N` | 当前存档，原样 JSON 字符串 |
  | `dao.slot.N.bak` | 自动备份 `[{ at, v, reason, data }]` |
  | `dao.slot.N.orig` | 迁移前的原始存档 |
  | `dao.slot.N.lock` | 最近写这个存档位的游戏页面 |
  | `dao.slots.meta` | `{ last, legacyImported }` |

- `parse(raw)` 返回 `{ status: 'empty' | 'ok' | 'error', save, error, errorText, migratedFrom }`。错误有 4 种：
  - `corrupt`：不是 JSON
  - `newer`：版本比代码新
  - `invalid`：同版本但数据不完整
  - `migrate`：旧版本迁移失败，或迁移时抛错
- `read(n)`：读一个存档位。需要迁移时先存原始数据到 `.orig`，然后只在内存里迁移；存档位里的数据要等游戏保存时才变成新版本。
- `write(n, save, now, { reason, force })`：
  - 存档位当前是读不出来的数据时拒绝写（`protected`），除非 `force`（玩家确认过）。
  - reason 是 `new` / `import` / `restore` / `tool` 或带 `force` 时，旧数据先进备份。
  - 其余 reason 写完后按间隔备份；`manual` / `title` / `migrate` 时强制备份。
  - 每次写都会盖上 `savedAt`。
- 其他接口：
  - `restore` / `restoreOriginal` / `remove`：动手前都先把当前数据存进备份。
  - `importText`：读不出来的文件不导入。
  - `list`：返回各存档位的摘要。
  - `lastSlot`：取 `meta.last`；没有记录时（清过浏览器数据、存档从硬盘读回）取最后保存时间最新、读得出来的那个。
  - `importLegacy`：只在第一次打开时把老存档复制进第 1 位，而且第 1 位必须是空的。

### 硬盘 `src/ui/save-disk.js`（`DAO.SaveDisk`）+ `tools/server.js`
- 只在 `http(s):` 打开、并且 `GET /api/saves` 有响应时启用（`disk.state = 'ok'`）。file:// 时是 `off`，连不上本地服务时是 `error`。两种情况游戏都照常运行，只用浏览器存档。
- 打开时 `sync`：

  | 浏览器 | 硬盘 | 处理 |
  |---|---|---|
  | 没有 | 有 | 用硬盘的 |
  | 有 | 有，都读得出 | 用 `savedAt` 新的那份；另一份进备份，或者靠硬盘端的自动备份留底 |
  | 读不出来 | 有 | 不动浏览器那份（不自动覆盖）；硬盘那份出现在「备份」面板，可以选用 |
  | 有 | 没有 | 写到硬盘 |

- 保存时 `put`：节流 3 秒，手动保存、回标题页时立即写并在 `saves/backups/` 留一份。离开页面时用 `beacon`。
- 服务端：
  - 先写临时文件再改名。
  - 硬盘上原来的文件读不出来时先移到 `saves/broken/`。
  - 删除时移到 `saves/deleted/`。
  - 存档位编号只接受 1–20。

### 界面 `src/ui/game-app.js`
- 启动流程：导入老存档 → 检查本地服务、和硬盘对一遍 → 标题页（`renderTitle`）。
- `openSlot(n)`：读不出来时不进游戏，留在标题页显示原因。
- `persist(reason)`：每 5 秒、操作后、离开页面时写。先登记 `lock`，再写存档。
- `storage` 事件的处理：
  - 存档工具改的（lock 还是本页）→ 重新读入。
  - lock 是别的游戏页面 → 本页回标题页。
  - 读不出来或被删除 → 本页停下，不写、不删。
- 回放速度等界面偏好还存在 `dao.speed` 之类的键里，不是存档。

### 存档工具 `tools/save.js`
顶部选存档位，也可以用 `save.html#slot=2` 直接打开某一位。每次修改先把旧数据存进备份，同时写硬盘。读不出来的存档位只能导出原始数据或导入覆盖。

### 持续制造（`src/game/game.js`）
- `save.production.jobs[线 id] = { line, slot, charId, cur, made, last }`，`cur = { cost, durMs, progressMs }`；`cur` 为 null 表示等待材料。
- 每条线 1 个工位，一个角色只能有一个任务（`jobOfChar`）。
- `startProduction(save, slot, charId, now)`：材料不够也能派，派过去先等材料。人会离开采集和上阵。
- `tickProduction(save, now)`：
  - 按游戏时钟推进，做完一件就掷品质、放进背包、马上开下一件（扣下一件的材料），多出来的时间顺延。
  - 等材料的任务材料够了自动开工。
  - 返回这次做好的装备列表。
  - 离线不计算：页面打开时 `resumeProduction`。
- `recallProduction(save, line)`：退还当前这件，人回到闲置。遣散打造中的角色时也走这里。
- `switchProduction(save, line, slot)`：退还当前这件，按新部位重新开工。
- `craftBlock` 不再看材料（材料不够也能派），只看工坊、工位是否占用、这个人能不能走开。另外新增了 `canAfford`。
- **推荐** `nextUpgrade`：
  - 背包里有更好的 → 穿上（`equip`）。
  - 这条线没人在做 → 派人（`craft`，材料够一件时才算 affordable）。
  - 已经有人在做、某个上阵角色的部位空着而工位在做别的部位 → 改做（`switch`）。
  - 其余情况返回 null：工位就这样一直做下去，做出更好的再提示穿上。
- **引导**：
  - `forge`（第一件装备）：材料够一件时才弹，派人后持续制造。
  - `gearUp:*`（卡关补装备）：用上面的推荐，常见的是穿上新做好的、改做空着的部位。
- **标准玩家模拟**（`cli/lib/play.js`）：要攒钱研究上阵位、金币又不够时先召回打造的人，攒够、开始研究后再派。全自动玩家只点引导，也能打完。
