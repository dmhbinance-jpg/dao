# 变更记录

## 阶段 1 —— 洞府开门（2026-10-24）

单人打到 1-4 卡关，被引导去洞府招募同伴、研究第 2 个上阵位，两人组队通过引导关第一段；加入自动推关。

### 新增
- **1-4 石甲关重做**：前排石甲猪（血厚、高护甲）+ 后排两只狐妖。剑修单人被后排远程磨死，法修单人被前排硬怪顶死；两人 Lv4 能过，单人要 Lv8–9 才能硬过。
- **金币**：打怪掉金币（敌人模板 gold × 等级 × 3），用于招募和研究。
- **洞府招募**：在 1-4 第一次战败时开放并弹引导。新手首抽免费、保底出与开局角色互补的定位；之后每日首次 100 金、每次 ×1.5、次日重置。品质凡 / 良 / 上 / 极（50 / 35 / 12 / 3%）决定成长资质区间、天赋条数和能否出触发型天赋，天赋池用 V0 的。招募角色等级 = 最高等级 − 1。名额上限 12，满了当场选择留下（遣散一个现有角色）或遣散新人。
- **研究「上阵位」**：每级 +1 上阵位，从 1 到 5；研究占用一个角色，期间不能上阵。第 2 级 20 金 / 60 秒，往后逐级变长变贵；智力越高越快。
- **多人上阵与布阵**：上阵 2 人起可以分前后排，默认剑修前、法修后，可单独换排或互换；1 人时不显示布阵。
- **经验分配**：只有上阵角色拿经验，每人拿全额（`exp.split` 开关可改为平分）。
- **自动推关**（默认开，可随时关）：胜了自动打下一关；最新关输了退回最高已通关的关卡挂机；上阵角色升级后再挑战一次；首领关和新系统引导前停下来等确认。
- **引导链**：洞府开门（免费招募）→ 研究第 2 个上阵位 → 布阵 → 首领确认 → 第一段通关。
- **界面**：顶栏（金币 / 上阵位 / 自动推关 / 关卡·洞府·角色）、吸顶活动条（推关 / 挂机进度 / 等待确认 / 研究倒计时）、洞府页（招募、研究）、角色页（布阵板、上阵 / 研究中 / 闲置分组）、引导弹窗、提示消息。
- **引导关第一段扩到 12 关**：难度阶梯从 1-4 起每关约 +0.5–1 级，首领山魈带两只灰狼。
- **存档 v2**（`dao.save`）：阶段 0 存档（`dao.s0.save`，v1）首次打开时自动迁移，打过 1-4 的直接开放洞府；旧键保留。
- **验收脚本** `cli/stage1.js`：1-4 单人 / 两人胜率表、布阵对比、标准玩家与全自动玩家模拟、单人对照、招募品质分组，写入 `docs/STAGE1_REPORT.md`。

### 改动
- `config/stage0.js`、`game/stage0.js`、`ui/stage0-app.js` 改名为 `config/game.js`、`game/game.js`、`ui/game-app.js`；`CONFIG.stage0` → `CONFIG.game`；`DAO.Stage0` → `DAO.Game`。
- 删除 `cli/stage0.js`（单人数据并入 `cli/stage1.js`）；阶段 0 报告移到 `docs/archive/STAGE0_REPORT.md`。
- 气血公式改为 (360 + 110 × 等级) × 定位倍率，拉长单场战斗；V0 报告已重跑。
- 击杀经验倍率 2 → 3；法修开局智成长 3.2 → 3.0。
- 新敌人石甲猪；敌人模板加金币字段。
- 修复：`[hidden]` 被组件样式覆盖导致隐藏的弹层挡住点击（全局加 `[hidden] { display: none !important }`）。

### 验收（`node cli/stage1.js 300`，全部通过）
- 1-4 通关等级 单人 / 两人：剑修开局 Lv9 / Lv4，法修开局 Lv8 / Lv4。
- 第一段总时长（标准玩家）：剑修开局 12.5 分钟、法修开局 10.4 分钟；挂机占比中位 21% / 18%。
- 全自动玩家（只在引导处点确认）100% 打完：11.2 / 9.1 分钟。
- 第一段通关等级：剑修开局 Lv11，法修开局 Lv10。
- 首抽资质最差 25% 比最好 25% 慢 1.2–2.4 分钟，全部能打完。
- 两人剑前法后比反过来平均高 59 个百分点胜率。
- 同种子结果一致；阶段 0 存档能迁移。

## 阶段 0 —— 单角色起步（2026-10-24）

开发节奏改为跟着设计文档第 15 节「开局成长阶梯」走。本阶段：玩家创建一个角色，打引导关、升级、挂机，完整玩 10–20 分钟。

### 新增
- **开局选角**：剑修或法修二选一，资质中等且固定，各带 1 条属性型天赋（力拔 / 慧根 +10%），不随机。开局角色和其他角色走同一套规则，没有主角特例。
- **技能**：只有普攻 + 固有主动（固定 A 分支：剑修「剑气斩·单」，法修「连珠火·散」）。不做技能卡、2选1、被动卡槽。
- **敌人**：灰狼、野猪、狐妖（远程，站后排）、首领山魈。三维 = base + growth × 等级，与玩家同一套公式，全部在配置表。
- **引导关第一段「青石山」**：8 关线性链，1 打 1 → 1 打 2 → 1 打 3 → 首领。有后排的关，剑修打倒前排后能打到后排。
- **经验与升级**：击杀得经验（战败时已击杀的也算），升级按成长资质加三维，气血随等级增长。经验曲线 round(10 × 等级^1.6)。
- **挂机**：已通关的关卡可以自动重复刷经验，按 2× 播放时长计时；刷新页面后继续挂机，不做离线收益。
- **界面**（`index.html`）：选角页、角色面板（三维、气血、技能、天赋、等级与经验条）、关卡列表、战斗回放（复用 V0 播放器）、挂机面板、战斗结算条。
- **存档**：`localStorage['dao.s0.save']`，带版本号，与 V0 存档分开。
- **验收脚本** `cli/stage0.js`：各关 × 各等级胜率表，模拟新玩家（打不过就挂机升一级再来）统计通关等级与用时，写入 `docs/STAGE0_REPORT.md`。
- **通用战斗回放组件** `src/ui/battleview.js`：从 V0 播放器抽出，V0 和阶段 0 共用；空的排不画。

### 改动
- 删除体修、丹修、阵修的角色（石敢当、林青囊、司徒衍、孟山、白素）、专属技能（磐石、回春、阵法）、普攻和仅限这些定位的技能卡（破甲符、固元符、回春丹、疾风阵、护盾符、灵枢）。
- 名将霍骁改为剑修；补了岳凌、秦霜、沈青崖（剑修）和温如玉、陆焚（法修），V0 默认阵容只用剑修和法修。
- 定位表只剩剑修、法修，另加敌人用的妖兽（近战）、妖修（远程）。
- 气血公式改为 (200 + 60 × 等级) × 定位倍率，适合从 1 级起步。
- 数据模型支持三种单位来源：内联角色（玩家）、V0 角色模板、敌人模板；敌人模板可在同一阵容里重复。
- V0 模拟器页面改名为 `v0.html`；配置表页的本机保存键改为 `config.v2`，避免读到删除角色前的旧配置。
- `cli/experiments.js` 只用剑修、法修；第 3 节「辅助走防御区」依赖辅助定位，标记为 V0 遗留、不再维护。V0 原始报告移到 `docs/archive/V0_SIM_REPORT_v0.md`。
- 播放节奏移入配置表 `CONFIG.playback`。

### 验收（`node cli/stage0.js 300`）
- 首领通关等级：剑修 Lv11，法修 Lv12（差 1 级）。
- 选角到打完第一段：剑修 13.3 分钟，法修 13.4 分钟。
- 同种子战斗结果一致。

## V0 —— 地基 + 战斗模拟器（2026-10-24）

### 地基
- **配置表** `src/config/`：所有数值集中在 `DAO.CONFIG` 一张表里，按文件分节：系数（`coef.js`）、普攻 / 固有主动 / 技能卡（`skills.js`）、天赋（`talents.js`）、示例角色与默认阵容（`characters.js`）。界面的「配置表」页可以直接改整张表并保存在本机。
- **带种子的随机数** `src/core/rng.js`：mulberry32。战斗里唯一的随机来源（暴击、随机目标、弹射、触发几率），同种子同阵容结果完全一样。
- **事件系统** `src/core/events.js`：开场、回合开始、出手时、暴击时、击杀时、受击时。带每回合次数上限和「触发不可递归」保护。
- **标签** `src/core/tags.js`：7 个标签（物理、法术、治疗、单体、群体、剑、火），形状标签由引擎按技能形状自动补上。
- **数据模型** `src/core/model.js`：角色模板（三维、2选1、技能卡档位、天赋档位）→ 战斗单位；阵容合法性检查。

### 战斗模块（`src/battle/`，不依赖界面，Node 可直接跑）
- 拉条：行动条按速度填充，满了出手；推条 / 拉条；CD 按角色自己的行动次数计。
- 双方各 5 人，前后两排、每排最多 3 人；近战单体只打前排，前排全灭后后排暴露；远程 / 穿透可打任意目标。
- 五种技能形状：单体、前排、后排、全体、弹射（随机命中 N 次、可重复、逐跳衰减）。
- 五个乘区：攻击×倍率 × (1+Σ增伤) × 暴击 × (1+Σ终伤) × k/(k+护甲或法抗)；buff 加算进各区，破甲最多减到 0；没有伤害随机浮动。
- 每个角色：普攻 + 固有主动（2选1）+ 主动卡槽 + 被动卡槽 + 1–3 条天赋（属性型 / 标签型 / 触发型）。
- 嘲讽、守护、护盾、治疗、增益 / 减益。
- 有界规则：再动每回合最多 1 次；触发不可递归；每单位每回合最多 3 次行动。
- 辅助贡献归因：把某个辅助施加的 buff / debuff 拿掉重算一遍伤害，差值记到施加者头上（减伤、破甲、增伤三项）。
- 批量模拟：胜率、平均回合、伤害占比、溢出、触发次数、技能每次伤害与变异系数、辅助贡献。可换边抵消先后手偏差。

### 示例角色（数值均为占位）
柳无影（后排刺客剑修）、苏烬（弹射法修）、石敢当（守护后排的体修）、林青囊（奶妈丹修）、司徒衍（同排加成的阵修）、霍骁（名将·破军），以及补位用的韩铁衣、赤霞子、孟山、白素。

### 界面（`index.html`，直接用浏览器打开）
- 阵容编辑：选人、换排、2选1、技能卡选择与档位滑条、天赋选择与档位、三维、计算后属性预览；技能标签与天赋标签匹配时高亮。
- 战斗播放：连续播放 1× / 2× / 4× / 跳过 / 暂停；行动条常驻，带接下来的出手顺序；战斗日志显示触发链（⚡ 行）。
- 批量模拟：分块运行不卡界面；胜率条、角色表、技能表、触发次数。
- 配置表：整张表 JSON 编辑、应用、导出、恢复默认。

### 命令行（`cli/`）
- `node cli/battle.js [种子]`：跑一场并打印完整日志。
- `node cli/sim.js [场数] [起始种子]`：默认阵容批量模拟。
- `node cli/experiments.js [场数]`：四个设计问题的验证实验，结果写入 `docs/V0_SIM_REPORT.md`。

### 数值调整
- 第一轮把战斗从约 18 回合压到约 13 回合：气血基础 1200→1000、每级 60→40，治疗强度每点智 2.0→1.6。
- 默认阵容 B 改成 2前3后，孟山带护体罡气、白素带护盾符、韩铁衣带剑心通明，让默认对局不至于 100:0（现在 A 80% / B 6% / 平局 14%）。
