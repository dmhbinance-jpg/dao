## 配置网站：启动和使用
```bash
node tools/server.js            # 默认端口 8765；换端口：node tools/server.js 9000
```
- 游戏：http://localhost:8765/ （和双击 `index.html` 一样）
- 配置网站：http://localhost:8765/tools/
- 只用 Node 自带模块，不用装依赖；只监听 127.0.0.1。

**调参页**（/tools/）
- 列出 `DAO.CONFIG` 全部约 1,600 项，按模块分组（左边是目录），可以搜索路径或中文名，可勾「只看改过的」。
- 每项显示默认值和当前值；改过的黄底，不合法的红底（类型不对、超出合理范围，例如时间倍率只能 1 / 2 / 5 / 10），有错时不能保存。服务端保存前会再校验一遍。
- 「常用」组置顶：时间倍率、研究时长 / 金币、采集速率、金币倍率、经验倍率、招募价格、锻造花费。
- 点「保存」→ 写回 `src/config/tuning.js`（只放和默认值不同的项）→ **刷新游戏页面生效**。单项「恢复默认」；「全部恢复默认」（点两次确认）把 tuning.js 写成 `DAO.TUNING = {};`。
- 默认值文件 `src/config/*.js` 由开发对话维护，配置网站不会改它们。

**存档工具**（/tools/save.html）
- 加金币 / 灵矿（可以填负数）、改角色等级、解锁关卡（这一关之前都算通关，途中开放的系统照常开放并排队引导）、立即完成当前研究、导出 / 导入（文件或粘贴 JSON，导入时自动迁移旧版本）、重置存档。
- **只对从同一个本地服务打开的游戏有效**：存档在浏览器 localStorage 里，按网址隔离。双击 `index.html`（file://）的存档在别处，这里看不到。页面顶部写了这一点。
- 游戏页开着也可以改：游戏监听 storage 事件，别的页面改了存档会自动重新读入（顺带也让两个游戏标签页不会互相覆盖）。

**tuning.js 的格式**
```js
DAO.TUNING = {
  "debug.timeScale": 10,
  "game.research.slots.levels.2.sec": 3,
  "assets.images[\"unit.sword\"]": "units/sword.png",
};
```
键是 `DAO.CONFIG` 里的路径（数组下标照写，键里带点的用 `["..."]`），由 `src/config/apply-tuning.js` 在默认配置之后合并进去。只改已存在、类型相同的叶子；不认识的项不生效，在控制台警告。数组长度不能通过 tuning 改。

**命令行**：`cli/*.js` 默认也读 tuning.js；加 `--defaults`（或环境变量 `DAO_DEFAULTS=1`）只用默认值。报告第二行会写明用的是哪套数值以及改了哪些项。

## 规则怎么落地
- **时间倍率**：`src/game/clock.js`。游戏时间 = 累加的「真实流逝 × 倍率」，每次读只加两次读取之间的真实流逝，真实时钟倒退时不倒退，所以运行中不会跳变。存档记 `clock: { game, real }`，重新打开时从存的游戏时间接着走（关闭期间的真实流逝按倍率计入，研究离线照样走；采集离线不算）。界面里研究、采集、招募、挂机计时、推关结算都用 `gnow()`；挂机定时器和推关后等待用 `clock.realMs()` 换成真实毫秒；战斗回放速度 = 按钮速度 × 倍率。倍率不是 1 时顶栏显示「时间 ×10」。命令行模拟始终按 1× 估时。
- **研究**：所有时长改为原来的 10%（6 / 60 / 60 / 180 秒）。上阵位上限：平时 3，打完第二段放宽到 4（`research.slots.chapterCaps`）。
- **招募 3 选 1**（`Game.recruit` → `save.recruitChoice` → `Game.chooseRecruit`）：付钱后用同一个招募种子生成 3 名候选存进存档；没选之前不能再招（不能放弃重抽），自动推关在这里等确认。默认选择（`defaultChoice`）：为采集招募（`reason: 'gather'`）选力成长最高的，选完直接去采集；其余选综合资质最高的。价格固定 `recruit.cost = 100`，删掉了每日首次 / 递增逻辑。首抽免费，3 名候选都是互补定位、都排除流影。
- **名额**：`roster.cap = 10`，`Game.rosterCap(save)` = 10 + `save.quota.extra`（扩建研究预留，恒为 0；配置里留了 `quota` 段）。名额满时 `recruitBlock = 'full'`，不能招募。老存档超过 10 人不删。选人时如果名额已满（例如在 tuning 里把名额调低了），沿用原来的「决定遣散谁」流程。
- **采集 / 锻造提前到 1-8**（`gather.unlockStage`）：1-8 首次通关时开放并排队 `gather` 引导。引导默认做法改成：先招一位（3 选 1，选完去采集）→ 闲人 → 调研究的人 → 从上阵撤人。然后是「第一件装备」引导（下品武器给开局角色）。原来 2-3 的「额外招募」引导删掉了（并进这里）。
- **卡点**：1-4 招人（不变）；1-12 首领要装备；第二段首领要技能卡（首领等级 +3）；第三段要第 4 个上阵位（敌人整体 +4 级，按 4 人设计；卡关时先引导研究上阵位，研究不了再引导补装备，`research.slots.stuckChapters`）。「研究上阵位」引导现在每升一级都可以再出现。
- **装备推荐**（`nextUpgrade`）改成一档一档补：先让每个上阵角色三个部位都有下品，再都换中品，再换上品。
- **锻造花费 / 数值、采集速率**（为了采集提前做的初步调整，以后用配置网站调）：下品 40 灵矿 / 100 金、中品 220 / 600、上品 500 / 1,200；下品数值调高（武器攻击 16、胸甲护甲 16 气血 200、戒指 +8）；采集每秒 0.7（原 1.0）。
- **存档工具用到的新接口**：`Game.onFirstClear`（某关第一次通关会开放的东西，从 `applyOutcome` 抽出来）、`Game.unlockCave`。

## 观察到的设计问题（带回设计对话）
1. **前两段变短**：研究时长缩到 10% 加上装备提前，第一、二段都从 12 分钟左右降到 9 分钟左右，挂机几乎没有。要回到 10–15 分钟，可以在配置网站里调研究时长、经验倍率或 1-9 之后的关卡。
2. **招募便宜**：固定 100 金、名额 10，第一段之后金币就不是招人的限制，限制只剩名额。标准玩家只招到 2 个采集的人是模拟策略里设的上限；真实玩家可能直接招满 10 人，这样灵矿会很充裕，金币变成唯一约束。
3. **卡点顺序和设计文档第 15 节不同**：文档写「等级 → 第二个人 → 技能卡 → 装备 → 更多上阵位」，本阶段按开发说明改成「第二个人 → 装备 → 技能卡 → 第 4 个上阵位」。需要在设计文档里改过来，或者再调回去。
4. **名额满时的选人流程**：说明里既写「名额已满时先选人再决定遣散谁」，又要求「满 10 人时不能招募」。我按后者做（满了不能招）；先选人再遣散的流程保留在代码里，只在名额被调低等情况下用到。
5. **全自动玩家第二段囤金**：不做可选研究，第二段结束约 9,000–11,000 金，第三段靠「研究上阵位」引导才花出去。
6. **上品装备几乎没人用**：第三段卡在上阵位上，金币先花在研究；上品主要是给以后的阶段。
